# Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a top-level Profiles tab where the user lists, creates (New or Save current setup), edits, deletes, and activates named combinations of one JDK and optional Maven, Ant, and Gradle versions, applied in one confirmed registry write.

**Architecture:** A JavaFX-free `dev.jdktrustmanager.profiles` package holds the store, resolver, active-profile matcher, current-setup capture, and activation decisions. All are pure functions over the model and paths, so the later top-bar switcher reuses them. `env` gains `EnvironmentPlan.forProfile`. The `ui` gets a `ProfilesPane` and a `ProfileForm` dialog that run every write through `UserPathWriter` on the `WorkQueue`.

**Tech Stack:** Java 21, JavaFX 21, Maven, Jackson 2.23, JUnit 6. No new dependencies.

**Spec:** [docs/superpowers/specs/2026-11-27-profiles-design.md](../specs/2026-11-27-profiles-design.md)

## Global Constraints

- Only `dev.jdktrustmanager.ui` may import JavaFX.
- State file: `%LOCALAPPDATA%\JdkTrustManager\profiles.json`, written with `JsonStores.writeJson` (atomic replace).
- A profile's JDK is required. Tools are optional: a null version means "not in this profile".
- Folders: JDK = `Layout.destination(root, vendorSlug, major)`; tool = `ToolLayout.destination(root, BuildTools.of(tool), version)`.
- Profile names are trimmed, non-blank, and unique ignoring case.
- Activation writes only through `UserPathWriter.live().write(current -> EnvironmentPlan.forProfile(current, …))`, on the `WorkQueue`. It never applies "remove other Java entries". Tools left out come off PATH (variables deleted, entry removed).
- Managed PATH order stays `%JAVA_HOME%\bin`, `%MAVEN_HOME%\bin`, `%ANT_HOME%\bin`, `%GRADLE_HOME%\bin`. Other entries keep their order.
- The active profile is computed from the registry on every refresh and never stored.
- Top-level tab order: Java, Maven, Ant, Gradle, Profiles, Activity.
- Every install, delete, or environment write asks first through `ConfirmDialog` (Cancel default). Blocking work never runs on the FX thread. Panes use `Spacing.page` / `Spacing.GAP`.
- Tests run with `mvn -B -ntp -f app/pom.xml test [-Dtest=Class]`. In the Claude desktop app, launch Maven outside the app package (WMI `Win32_Process Create`). All verification is automated; the user does the UI checks.

## Review Focus

- **A profile pointing at a JDK that is on disk but not in `installations.json`** (deleted record, folder still there): it counts as installed if the folder is a JDK home, so activation isn't blocked by a missing record. Test in Task 2.
- **Paths that differ only in case or a trailing backslash** (`c:\java\temurin-8\`) still match for "active" and "installed". Test in Task 3.
- **An edit that renames a profile to its own name in different case** (`release 4.2` → `Release 4.2`) is allowed, not refused as a duplicate. Test in Task 1.
- **A profiles.json that's unreadable or from a newer version** must not crash the tab. It reads as an error message, and the file is never overwritten until the user saves. Test in Task 1.
- **Activating when an install the job depends on failed or was cancelled** writes nothing. Test in Task 6.

### Task 6: Activation decisions and the prompt

**Files:**
- Create: `app/src/main/java/dev/jdktrustmanager/profiles/ProfileActivation.java`, `profiles/JdkSource.java`
- Modify: `app/src/main/java/dev/jdktrustmanager/ui/Confirmations.java`
- Test: `app/src/test/java/dev/jdktrustmanager/profiles/ProfileActivationTest.java`, extend `ui/ConfirmationsTest.java`

**Interfaces:**
- Consumes: `ProfileResolver.Resolved`, `BuildTool.javaRange`, `Distribution`, `Slug.of`.
- Produces:
  - `ProfileActivation.changes(Resolved resolved) -> List<String>`. One line per slot: `"temurin 8 → JAVA_HOME"`, `"Maven 3.3.9 → on PATH"`, and for each tool left out, `"Gradle → off PATH"`. The order is JDK, Maven, Ant, Gradle.
  - `ProfileActivation.javaWarnings(Profile profile) -> List<String>`, for example `"Maven 4.0.0 needs Java 17 or newer; this profile's JDK is Java 8."`.
  - `ProfileActivation.readyToWrite(Resolved resolvedAgain) -> Optional<String>`. It's empty when every slot is installed. Otherwise it gives `"Not activated: Maven 3.3.9 isn't installed."`, listing every missing label. The activation job calls this after any queued installs and writes nothing when it isn't empty (Review Focus: failed or cancelled install).
  - `JdkSource.find(List<Distribution> vendors, JdkRef jdk) -> Optional<Distribution>` matches `Slug.of(apiParameter, javafx, "x64")`, where `javafx = vendorSlug.endsWith("-fx")` (and `-arm64` maps to `"arm64"`), against `vendorSlug`. `JdkSource.javafx(JdkRef)` and `JdkSource.architecture(JdkRef)` are its helpers.
  - `Confirmations.activateProfile(String name, List<String> changes, List<String> javaWarnings, String newPath) -> Prompt`, with title "Activate <name>" and action "Activate".
  - `Confirmations.installMissing(String name, List<String> missingLabels, List<String> cannotInstall) -> Prompt`, with action "Install and activate". When `cannotInstall` isn't empty, the message says which slots can't be installed automatically.
  - `Confirmations.deleteProfile(String name) -> Prompt`. The message says the environment isn't changed.

  - the change lines for temurin 8 + Maven 3.3.9 with no Ant or Gradle;
  - the warning for Maven 4.0.0 on JDK 8, and none for Maven 3.9.9 on 8;
  - `readyToWrite` is empty when every slot is installed and gives the message when Maven is missing;
  - `JdkSource.find` picks `liberica` for `liberica-fx` and returns empty for an unknown slug;

**Files:**

**Interfaces:**
- Consumes: everything above, plus the stage 1 `ToolContext`, `InstallJob`, `ToolInstaller`, `ToolCatalog`, `CatalogBrowser`, and `DiscoClient`.
- Produces:
  - `AppTabs.context(Path root, JsonStores stores, WorkQueue queue, Supplier<Settings> settings) -> ToolContext`, built once and shared.
  - `AppTabs.toolTabs(ToolContext)`.
  - `AppTabs(Node java, List<ToolTab> tools, Node profiles, Node activity)`.
  - `ProfilesPane(ToolContext context, ProfileStore store, CatalogBrowser browser, DiscoClient client)`.
  - `ProfileForm.show(Node owner, Profile initialOrNull, List<Installation> managed, Map<Tool, List<String>> installedVersions, List<String> notes) -> Optional<Profile>`.

Behavior, from the spec's Screens and Activating sections:
- **The pane:**
  - The top row has New, Save current setup, Edit, Delete, Activate, and a status label.
  - Above the list sits an "active" line, which reads "No profile matches the current setup" when none does.
  - The list rows read `"<name>   <describe>"`, plus `[active]` and `[missing: <labels>]`.
  - Under the list, a details text area shows each slot's folder and the `forProfile` PATH preview built from the current user Path.
  - The pane refreshes after every change and every queue job it submits.
  - When `ProfileStore.read()` throws, the pane shows its message and disables New, Save current setup, Edit, Delete, and Activate, so a damaged `profiles.json` is never overwritten (Review Focus).
- **The form:**
  - It's a `Dialog` with a name field and a JDK combo box listing managed JDKs as `"<slug> <major> — <path>"`, plus a hint when the list is empty.
  - The Maven, Ant, and Gradle combo boxes offer "(none)" plus installed versions. A slot from the initial profile that isn't installed shows as `"<v> (not installed)"`.
  - A warning label shows `javaWarnings` and updates live.
  - OK runs `ProfileStore.validate` and stays open with the message when the profile is invalid.
- **Activate:**
  1. Resolve the profile.
  2. If slots are missing, show `installMissing`. On confirm, queue an `InstallJob` for the JDK, using `JdkSource` plus `browser.latest(distribution, major, settings, javafx, false)`, and a `ToolInstaller` job for each tool, using `ToolCatalog` releases by version. Slots `JdkSource` can't find go in `cannotInstall`, and the activation isn't queued.
  3. Show `activateProfile` with the changes, warnings, and preview.
  4. Queue the activation job. It resolves the profile again, calls `readyToWrite`, then runs `UserPathWriter.live().write(current -> forProfile(...))`. After that it calls `Installations.markActive` and `ToolInstallations.markActive` for every tool, setting each to its folder or null.

- [ ] **Step 2: Run `-Dtest=SmokeTest`.** Expected: FAIL.
- [ ] **Step 3: Implement** the pane, the form, the `Screens` change, and the `AppTabs` and app wiring.
